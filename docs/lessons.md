# Lessons

One line per change to an API, format or agreed behaviour; the full story of each is in `docs/lessons-full.md`.

- **2026-11-06 multiCMD: a command that differs from another only in case is a script file, not an entry point**: a command name is also a config key to the tools that install it. pip 9 (stock on EL7 and EL8) reads `entry_points.txt` case-folded and fails on upgrade or uninstall, so keep one spelling as the entry point and ship the other as a script file.
- **2026-11-10 multiCMD: a child that runs code before its exec waits for its parent's go-ahead**: a start interrupted after the fork loses the child. Where the child runs code first (an exec wrapper), have it wait for one byte on a pipe that the parent writes once it has the child registered; an interrupted start closes the pipe, and the child exits without running anything. Measure a race's window on the oldest, slowest platform supported, inside the real program.
- **2026-11-10 multiCMD: start threads where no signal handler runs**: `threading.Thread.start()` is Python code that takes a lock and waits on an Event in the calling thread, and a Ctrl-C on the main thread can leave either held, blocking every later thread start. On the main thread, start threads with `_thread.start_new_thread` (one C call), or run `threading.Thread.start()` on a helper made by that call, and store what the call made before Python can raise.
- **2026-11-10 multiCMD: the embed decodes with zlib, not lzma**: code embedded for any Python decodes with what every target has; zlib, which pip itself needs, not lzma, an optional build module.
- **2026-11-11 multiCMD: a helper Python starts with SIGINT blocked**: a Python that SIGINT reaches while it initializes aborts with a core dump (3.6, 3.7) or exits 1 with "Fatal Python error" (3.8 - 3.10). When a program may stop a Python child it just started (with SIGINT first), start the child with SIGINT blocked through the inherited signal mask and have it unblock SIGINT once it can be stopped cleanly. Count a test's crashes, not only its time: a CI runner's crash handler turns each core dump into seconds of CPU.
- **2026-11-11 multiCMD: a filter that supervises children treats a closed stdout as a stop**: Python answers a stdout it cannot flush with a traceback and status 120, and a reader thread that dies on the error stops nothing. Have every thread that writes report a closed stdout to the main thread, by a flag its waits poll and raise from (a raise from a signal handler can be dropped in a `__del__`, or land inside a start), stop the children as for a Ctrl-C, then end by SIGPIPE ( default action restored, signal sent ), so a shell sees 141 and stderr stays empty.
- **2026-11-11 multiCMD: a filter asks its stdout whether the reader quit**: a pipe's write end reports its reader closing without any write: while waiting on children, poll it (POLLERR on Linux, POLLHUP on macOS), and only when stdout is a pipe: a hung-up terminal and, on macOS, a half-closed socket answer POLLHUP too, and a job left running on purpose outlives its terminal. Take each platform's form of the failed write (EPIPE, Windows' EINVAL) as the same closed stdout. Probe every kind of stdout (pipe, FIFO, terminal, socket, file, device), not only every platform.
- **2026-11-12 multiCMD: a failed write of the display loses the output, never the work**: classify a failed stdout write once, where every write passes: a reader that quit (EPIPE, ECONNRESET; Windows' EINVAL from a pipe) is a stop request; anything else (a terminal that hung up, a full disk) drops the output from then on, says so once on stderr, and lets every command finish with its own status. Point the dead descriptor at `/dev/null`, stdout's and stderr's (the same target is common: `> log 2>&1`), so Python's flush at exit cannot fail again (120). A hung-up terminal still sends SIGHUP to its shell and its foreground job, and bash and zsh pass it on to every job: only a job nobody signals (`setsid`, `nohup`, `disown`, and in bash and dash a job left behind by `exit`) runs on.
